# 编排层：愿景、架构、契约、CEO、可靠性

## 1. 愿景与目标

构建 **一人公司式多 Agent 协作**：用户主要对接 **CEO（可由自建 Agent 严格实现）**，CEO 向 **异构、可跨机** 成员下发任务；通过 **外置状态、机械验收、博弈与异议记录**（见 governance）降低长程失败率，抑制 **迎合与一致幻觉**。

### 核心目标（可量化）

| 指标 | 表述 |
|------|------|
| 长程任务成功率 | **≥ 90%**（任务类有界且验收可验证时） |
| 基线参考 | 单树弱门禁约 **≤ 50%** |

**边界**：无客观验收的开放任务不承诺 90%；允许 **极少次系统触发澄清**；不承诺「彻底解决」。

### 成功定义（统计前须约定）

1. **任务类**  
2. **验收**：自动化优先；其次可观察现象；避免纯主观唯一标准  
3. **重试与检查点**  
4. **统计口径**（一次算成功 / N 次内修复算成功）

### 用户体验目标

- **一句话** 启动；**主动提问**（选项+默认）补契约；**少让用户自备长规格**。

## 2. 架构总览

| 角色 | 职责 | 实现倾向 |
|------|------|----------|
| 用户 | 一句话 + 回答引导提问 | 人 |
| **CEO** | 调度、门禁、合并结论、对用户单出口 | **自建优先**（状态机 + 校验 + 可选 LLM） |
| **成员** | 子任务；同伴 **有限次商量** | OpenClaw / opencode / 自建；可跨机 |

**相对 subagent 树**：单点调度、外置状态、运行时门禁、机械关卡+异议、能力注册表路由异构。

**跨机**：能力注册表（成员 ID、任务类型、接入方式、输出 schema、凭证）；消息带 **`task_id` / `correlation_id`**；凭证按机隔离。

**商量防风暴**：最大跳数/条数，超出升级 CEO；禁止无 task_id 长聊；环检测。

**与 `docs/`**：`docs/company-agent-platform.md` 为 **业务落地**（小红书/GitLab/chat）；本篇为 **可靠性原则**。

## 3. 隐性契约与引导式澄清

**目标**：一句话进入 → 系统提问补全 → **用户回答 + 推断** 落盘为 **SSOT**。

**前提约定**：组织级默认（仓库、CI、禁改目录等）可复用；每任务契约须 **引用** 其版本。

**提问原则**：**选项 + 默认 + 一句纠正**（避免空问「还有什么要求」）。

**契约最小字段**：原始一句话；对齐目标；范围；环境前提指针；验收；非目标；重试/检查点；待决项（长执行前应清空）。

**少人干预**：干预 = 答问；无验收或歧义过高须 **澄清** 而非瞎猜。

**存储**：`contracts/{task_id}.md` 或 DB；建议 Git。

## 4. 自建 CEO 规格

**为何自建**：纯 LLM 监工易 **迎合、形式化检查**；价值在 **代码/规则 enforce**。

**硬能力**：任务图/阶段机；外置状态；契约完整性门禁；产物 schema/脚本/测试；商量计数/超时在 **网关或代码**。

**合并与出口**：须处理 **异议区块**（governance）；对用户宣称成功须满足门禁或 **带风险通过**（记残余风险）。

**软能力**：歧义、验收失败、重复失败时 **引导澄清**。

**LLM 可用**：理解、分解建议、草稿、对话。**不可**仅凭口头判定「下一阶段 / 成功」。

**失败**：重试、换成员、缩小范围、升级用户；成员不可用则降级排队。

**OpenClaw**：宜作 **成员**；CEO 宜 **独立编排层**。

---

## 5. 长程可靠性原则

**典型死因**：上下文断档；错误累积；验收模糊；自由扩 scope；迎合幻觉；终审放水。

**原则（序）**：外置 SSOT；机械验收优先；检查点与有界重试；对用户单出口；商量有界；异议必录；**成功由契约+自动化+状态决定**。

**反模式**：唯一质检=「请再检查」；无 task_id 私聊；决议吞掉未决反对；一句话不落盘就开跑。

**监控**：阶段耗时、失败类型、重试、异议、带风险通过；按任务类调契约与门禁。
